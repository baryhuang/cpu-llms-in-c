Model-specialized inference, measured on the hardware it ships on.

The current llm-in-c portfolio spans Apple M3 Pro, NVIDIA Jetson Orin, Rockchip RK3588 and Amlogic A113X. Every headline below is tied to one checkpoint, target and execution path; unlike the previous report, this page is not a review of only the legacy Gemma artifact.

Unsupported formats are reported explicitly rather than relabeled. Native w8a8 requires a representative calibration set; no calibrated large-v3-turbo graph was fabricated for this one-file task.

The w4a16 capability result was reproduced on 2026-08-21 with the proprietary librknnrt 2.3.2, RKNPU driver v0.9.8, native B/A/C layouts and a canonical 1×64×64 official-SDK positive/negative probe. The full Whisper baseline and LLMC runners fail at the same context-creation boundary, before std30.wav inference can start.

The retained capability result applies only to the fused vendor dtype. The separate custom runtime below owns INT4 unpacking, scale application and three-core scheduling, while RKNPU2 receives supported FP16×FP16 shards.

The MatMul API rejects combined masks 0+1 and 0+1+2, so the runtime creates three independent contexts, pins one to each core and splits every linear and attention output along N. The retained v2 1×1280×51904 gate completes in 5.351 ms versus 12.305 ms on Core0 alone (2.300×), with CPU/NPU cosine 0.999999978. Retained v2 LLMC is 3.565× faster end to end than its custom-runtime baseline; decoder time improves 16.830×. Both runs use only std30.wav and no target-side Python.

AOT v3 is the appended current result; the two earlier rows remain unchanged as historical measurements. The v3 builder stores each 32×32 INT4 tile next to its 32 FP32 scales so CPU dequantization reads sequentially. Inference creates no contexts, threads, queues or DMA allocations: one long-lived host thread owns each NPU core, nine shape plans share A/C workspaces, and 1,611,694,080 bytes of expanded B shards remain resident. The three adjacent LLMC trials are 43.776, 42.441 and 42.480 s; their 42.480 s median is 3.794× faster than the fresh 161.158 s v3 baseline and 1.874× faster than the retained 79.596 s LLMC row. It remains 2.369× slower than the 17.933 s fused FP16 graph, because RK3588 still executes the custom W4 path as many FP16 MatMul calls rather than a fused graph.

Execution-scope clarification: this result is AOT W4 storage followed by initialization-time expansion into resident FP16 weights; packed INT4 never enters the RK3588 NPU. The three NPU cores execute FP16 MatMul shards and do improve the same custom gate from 12.305 ms on Core0 to 5.351 ms on Core0/1/2 (2.300×). The faster 17.933 s control is not single-core: it uses RKNN_NPU_CORE_ALL inside fused vendor graphs. In the 42.480 s custom run, 3,172 linear calls consume 24.628 s and 30,080 attention MatMuls consume 13.682 s; decoder average loads are only 7.88/7.88/7.52%. The remaining gap is fragmented dispatch, host/NPU boundaries and expanded-FP16 bandwidth, so this row must not be described as native NPU W4A16.

Appended Mali-G610 path: unlike the NPU rows, the decoder GPU kernels directly read the v3 packed INT4 records and apply group-32 scales during multiplication; there is no decoder W4→FP16 weight expansion. Static scope selection keeps encoder linear/attention on the faster three-NPU path and moves decoder linear plus attention to four GPU compute units. The three trials are 26.213, 26.252 and 26.189 s; the 26.213 s median is 1.621× faster end to end than AOT v3 NPU-only, while decoder time falls from 20.733 to 4.267 s (4.859×). Decoder W4 linear alone improves from 18.014 to 3.094 s (5.823×). All formal trials emit identical token IDs. Target execution is native C++/OpenCL with no Python.

The tested proprietary Arm OpenCL userspace is g24p0-00eac0 on the board's g25p0-00eac0 kernel DDK; its private blob SHA-256 is 07cc993b…47c6614. The blob is not committed and must be supplied under its vendor license. All-GPU linear (51.118 s) and GPU encoder attention (41.127 s) were measured and rejected; the fixed hybrid is based on those results rather than dynamic scheduling.

A113X optimization decisions

KEEP · double-precision NEON stem The isolated 1,100-frame A/B/B/A mean fell from 28.806828 to 19.074221 seconds (1.510249×), with checksum 1635322.4827359049 in every run. The gain transferred to full Q4 and Q5 transcription.
REJECT · four-row × four-output GEMM It was up to 14.8% faster in the short kernel benchmark, but full Q5 compact transcription regressed from 255.093171 to 257.359803 seconds (+0.889%). The implementation was removed from the release source.
REJECT · selecting output tile size from an isolated sweep Tile 32 beat tile 64 in one four-layer two-row microbenchmark (4.627 vs 4.777 seconds), but the ordering interacted with row reuse. No tile-only change was promoted without an end-to-end win.

No transfer of A113X gains to another Arm SoC
