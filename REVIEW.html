Review conclusion: the runtime does not accept arbitrary text. It accepts IMAGE [CASE_INDEX|all]. The compiler tokenizes the twelve observations below and writes those token sequences into the model image. At runtime, the second argument selects one stored sequence; it is parsed as an integer or the literal all. There is no text or stdin input path.

How the test was run

1. Compile the fixed profile

python3 tools/compile_gemma4_task_image.py \
  --checkpoint /path/to/model.safetensors \
  --config /path/to/config.json \
  --tokenizer /path/to/tokenizer.json \
  --profile models/gemma-4-e2b/profile.json \
  --output hazard-v1.g4task

2. Build and execute all stored cases

make OMPFLAGS=-fopenmp build/gemma4-task
OMP_NUM_THREADS=2 \
  build/gemma4-task hazard-v1.g4task all

Accepted

Rejected before inference

build/gemma4-task hazard-v1.g4task \
  "A person is inside the hazard zone"

case index is outside the image

This follows directly from the runtime parser: any second argument other than all must parse completely as an in-range integer case index.
