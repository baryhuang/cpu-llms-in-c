Gemma 4 E2B bounded-runtime test review

Exact inputs and recorded outputs for the first complete 35-layer C/Q4 task artifact. Measurement date: 2026-08-10.

Review conclusion: the runtime does not accept arbitrary text. It accepts IMAGE [CASE_INDEX|all]. The compiler tokenizes the twelve observations below and writes those token sequences into the model image. At runtime, the second argument selects one stored sequence; it is parsed as an integer or the literal all. There is no text or stdin input path. The application output is one bit: 0 = safe, 1 = danger.

What the output actually is

Current diagnostic path:
  safe_logit:   FP32
  danger_logit: FP32
  decision:     danger_logit > safe_logit ? 1 : 0

Application output:
  one bit       0 = safe, 1 = danger

Exact decision-only rewrite:
  score = (W_danger - W_safe) · normalized_hidden
  score > 0 ? 1 : 0

The final soft cap is monotonic, so it does not change which raw projection is larger. The recorded extra decode feeds the selected label token through 35 layers for measurement; it is not required to return the bit.

How the test was run

1. Compile the fixed profile

python3 compiler/compile_gemma4_task_image.py \
  --checkpoint /path/to/model.safetensors \
  --config /path/to/config.json \
  --tokenizer /path/to/tokenizer.json \
  --profile models/gemma-4-e2b/profile.json \
  --output hazard-v1.g4task

2. Build and measure all stored cases

make OMPFLAGS=-fopenmp build/gemma4-task
/usr/bin/time -v env OMP_NUM_THREADS=2 \
  build/gemma4-task hazard-v1.g4task all

Input-boundary example

Accepted

build/gemma4-task hazard-v1.g4task 0
build/gemma4-task hazard-v1.g4task all

Rejected before inference

build/gemma4-task hazard-v1.g4task \
  "A person is inside the hazard zone"

case index is outside the image

This follows directly from the runtime parser: any second argument other than all must parse completely as an in-range integer case index.
